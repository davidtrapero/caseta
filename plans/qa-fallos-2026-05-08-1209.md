## Cambios aplicados

### Skill `qa-e2e` reescrita

[app/.claude/skills/qa-e2e/SKILL.md](../app/.claude/skills/qa-e2e/SKILL.md) ahora orquesta:

1. **Limpia** `app/tests-e2e/qa-cases/` (catálogo es única fuente de verdad).
2. **Despacha en paralelo** un subagente traductor por módulo. Cada uno lee `docs/qa-cases/<módulo>.md` y produce `app/tests-e2e/qa-cases/<módulo>.spec.ts` reutilizando los helpers `loginUI` y `resetServerDb` ya existentes.
3. **Ejecuta** `npx playwright test --reporter=json`. Playwright arranca el webServer, paraleliza con workers, captura traces y screenshots automáticamente.
4. **Consolida** el JSON del reporter en `informe.md` por módulo.
5. **Lanza analista** si hay fallos. El analista ahora recibe también el `spec-generation.json` para distinguir fallos por mala traducción (problema de la skill) vs regresiones (problema de la app).

## Pre-requisito pendiente — `playwright.config.ts`

El cliente Better Auth en [app/src/lib/auth-client.ts:6](../app/src/lib/auth-client.ts#L6) usa `process.env.NEXT_PUBLIC_APP_URL` con fallback `http://localhost:3000`. El [app/playwright.config.ts](../app/playwright.config.ts) actual define `webServer.env` con `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` pero **no** `NEXT_PUBLIC_APP_URL`. Sin esta variable, todos los logins de la suite fallarán con `Failed to fetch`.

**Acción del usuario** (cambio de 1 línea en `app/playwright.config.ts`):

```ts
webServer: {
  env: {
    ENABLE_TEST_ENDPOINTS: "true",
    DATABASE_URL: process.env.DATABASE_URL ?? "",
    BETTER_AUTH_SECRET: process.env.BETTER_AUTH_SECRET ?? "",
    BETTER_AUTH_URL: `http://localhost:${PORT}`,
    NEXT_PUBLIC_APP_URL: `http://localhost:${PORT}`,  // ← añadir esta línea
  },
}
```

Esto es edición de configuración del proyecto, no parte del run de QA. La skill detecta la condición al fallar y reporta, pero no parchea.
